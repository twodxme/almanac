01 Navigation & page chrome

Almanac has four content views behind one sidebar. The header's buttons were shown and hidden from wherever the switch happened to be written.

Page chrome was managed from seventeen scattered calls

Closed

Six methods each toggled update_btn, sort_btn and store_back independently. Any path that forgot one left a page wearing another page's toolbar — a correctness bug, not a polish item.

17 set_visible calls across 6 methods→8, of which 5 are _show_page itself
FixOne PAGES table declares each page's view, title, search placeholder, primary action and whether it has a filter drawer. _show_page() is the only thing that touches header state.

App Store and AI were unclickable

Closed

Sidebar rows are greyed out when their inventory count is zero. The App Store has no inventory count by definition, and agent was missing from the per-source count loop — so both primary destinations were insensitive. The App Store's icon was also shop-symbolic, which the icon theme doesn't have, so it drew a broken-image placeholder.

counts["agent"] = 0 → row.set_sensitive(False)
FixCount-less destinations are exempt from the sensitivity rule; inventory.AGENT added to the count loop; icons verified against Gtk.IconTheme.has_icon() rather than assumed.

No page had a name

Closed

The search entry was the header's title widget, so nothing named the current page, and the search box stayed active on the two pages where it does nothing.

FixAn Adw.WindowTitle carries the page name and a live summary. The title follows the sidebar row, not the stack child — "Updates", not "Software". Search moved to a shared bar that hides on pages that can't use it.

Maintenance couldn't collapse

Closed

Group headers are only activatable when they hold more than one item — deliberate, but it made the one-item Maintenance group look broken.

FixMaintenance gained a Health check page alongside Orphans, so the rule now produces the right behaviour instead of an exception.

02 Feedback

How the window tells you what it is doing, and what just happened.

Four status labels in four positions

Closed

Each page owned a dim label in a different place. Forty-seven messages went to them, mixing standing state (how much is installed) with events ("Could not remove X") — so failures were written to a grey line the user had already looked away from.

4 labels · 47 set_text calls 0 labels · 31 toasts · 17 scoped summaries
FixEvents go to an Adw.ToastOverlay; standing state goes to the header subtitle. Summaries are scoped to the page that owns them — the package scan finishing after you'd opened the App Store used to overwrite the store's summary.

Only one page of four showed it was working

Closed

Every page loads asynchronously. Only the AI page had any indication; the others sat still, looking finished, for up to twenty seconds.

FixOne spinner beside the window title, raised and lowered by every loader. The AI page additionally renders each of its six groups as it arrives, so the fast ones aren't queued behind the MCP health check.

Rows with untrusted text rendered empty

Closed

Adwaita rows parse title and subtitle as Pango markup. Every string in them comes from somewhere else — a skill description, a marketplace listing — so an unescaped & or <name> blanked the row. Markup must be switched off before the text is assigned; doing it after is too late.

Adw.ActionRow(title=…, subtitle=BAD) → parsed, row blank _plain(title=…, subtitle=BAD) → literal
FixA _plain() constructor builds the row, disables markup, then sets the text. Used everywhere external text lands.

03 Actions

Where the things you can do live, and whether every row offers one.

Primary actions sat in three different places

Closed

"Update all" was in the header; "Update harnesses" and "Reclaim space" were left-aligned in their own page toolbars. Three page-level actions, three positions.

toolbar widgets store 9→drawer maintenance 3→0 ai 3→0
FixOne header button whose label, tooltip, sensitivity and handler come from the current page. The App Store's eight filter controls moved into a drawer behind the same button slot that holds sort elsewhere, so no page has two "options" buttons.

A local checkout far behind upstream offered nothing at all

Closed

A local git checkout with uncommitted edits gets no pull button — the pull is refused either way. Its action menu, though, was built only from a project URL such a repository does not have, so the menu came up empty too. The row had a problem, no affordance, and no explanation.

FixLocal checkouts always get a menu: open the repository, show the diff, and — when dirty and behind — stash and update. Stash rather than discard, because the edits are someone's work and git stash pop brings them back.

Removal moved out of the terminal without losing its confirmation

Closed

Install and removal now run in-app. The safety property that mattered was pacman's y/N prompt — so it was moved, not dropped: a dialog shows the full pacman -Rs --print output, including dependencies, before anything runs.

FixThe two tests that encoded the old terminal-based invariant were rewritten to assert the new one — that nothing executes before confirmation, and that a failed preview abandons the removal entirely.

Four row buttons carry no tooltip

Accepted

Install, Remove, Update and the per-card action button. Their labels say exactly what they do, and a tooltip restating a two-word label is noise.

04 Visual language

The parts that are still inconsistent, honestly.

Secondary pages used a settings layout

Closed

The AI page was an Adw.PreferencesPage, which clamps content to a narrow centred column. Correct for a settings dialog, wrong beside a full-width table — the two read as different applications.

FixA shared _section() builder: full width, boxed list, heading and description, 12px margins. AI and Health check now use it; the App Store's card grid and the package table keep their own, because a grid and a sortable table genuinely are different things.

Spacing has no scale

Open

Margins in use are 4, 5, 6, 8, 10, 12, 14 and 16; gaps are 3, 4, 5, 6, 7, 8, 10 and 20. Each was chosen locally and looks fine locally. There is no scale they all derive from.

NextPick a 4px scale, map every value onto it, and keep the handful that genuinely need to be off-grid.

Nine badge classes with overlapping meaning

Open

crit-pill, stale-pill, crit-core, count-badge, store-chip, store-installed and three trust-* classes, across three font sizes (0.68, 0.70, 0.72rem).

NextCollapse to three semantic levels — neutral, attention, critical — plus one accent variant, at a single size.

05 Keyboard

No way to reach a page without the mouse

Closed

Six shortcuts existed and were fine. None of them navigated, and Ctrl R always re-scanned packages regardless of which page you were on.

Ctrl F · Ctrl R · F5 · Ctrl U · Ctrl W · Esc + Ctrl 1–6 to each destination; Ctrl R / F5 refresh the current page

06 Responsiveness & layout

The window could not shrink below its widest page

Closed

A Gtk.Stack reports the largest minimum width of all its children, shown or not. The App Store's eight-control filter bar therefore set the minimum width of every other page, and content was clipped rather than reflowed.

Fixset_hhomogeneous(False) so the stack sizes to the visible child, filter bars that can wrap, and a 480px floor on the window.

The card grid laid out one column at any width

Closed

Two independent causes, found by measuring rather than by eye. GtkPicture reports its paintable's intrinsic size as its natural width, and the marketplace ships 1600px screenshots — so every card asked for 1600px. Separately, the chips and button in the card footer had no ellipsize, and a box's minimum is the sum of its children's.

card minimum 425px→224px columns at 690px 1→3
FixThe artwork sits in a non-propagating ScrolledWindow so it gets no vote on card width, and is decoded at 420px so 160 cached textures aren't a gigabyte. Footer chips ellipsize; the button can shrink.

07 Speed

Three modules called api.github.com independently, each with its own cache and no idea what the others had spent. The limit is 60 requests an hour unauthenticated, and one ArtCraft refresh costs fourteen.

A rate-limited refresh cached blanks

Closed

Hitting the limit mid-fetch wrote entries with empty versions, and that stuck for six hours. Found because two ArtCraft apps showed no version after a forced refresh.

FixA failed lookup falls back to the previously cached row, so a rate-limited refresh degrades to stale rather than to empty. The shared cache also refuses to spend the last eight calls.

08 Still open

omarchy update still opens a terminal

Open

Everything else — plugins, AppImages, packages, AUR, Flatpak, git pulls, orphan cleanup, agent CLIs and Almanac itself — runs in-app. The full system updater manages its own sudo, which wants a TTY, so it is the one remaining handoff.

OptionsA sudo→pkexec shim on the PATH it runs with would close it, at the cost of putting a clever indirection in front of the riskiest operation on the machine. Not done without a decision.
